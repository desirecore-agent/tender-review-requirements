# 补遗处理

## L0
确认适用性、真实发布/版本关系及明确范围后才能应用变更。条款号、标题、无歧义内容描述及范围明确的一般通知均可识别受影响义务；不要求逐字引用旧条款。仅凭标签、日期或语言不判定优先级。

## L1
- 阅读原始文件及全部相关补遗，区分核实的发布事实与假设；较新的时间戳不证明效力或权威。
- 精确判明替换、有限修改、澄清或撤回及其范围，不扩大效力。保留范围外的条件、例外和义务；同时定位原义务及补遗中“未改”范围说明。
- 多份补遗按有证据的版本/生效关系处理；关系或语言优先级未明时不选时间最新文本。候选解释写入 notes，报告列为待有权人工决定事项。
- 完全替换保留原条款行，状态为 `superseded`，`superseded_by` 指向真实替代行。`supersede_relations` 两端 ID 都须存在；其有向边集与矩阵链接相等，不能冲突或成环。
- 部分修改将受影响成分及替代记录与继续有效的原义务分开。替代行只引用自身补遗原文，不编造合并引文。剩余义务保留原始来源与引文，`notes` 记录补遗文件/位置及未改范围说明；依赖合并效力的发现同时引用两行/双来源。
- 不改变义务的澄清只在 `notes` 记录来源和影响，不因存在通知就建立替代边或停用原义务。只有解释确实替代旧解释、两行确实表示该转换时才用 `clarifies` 关系。
- 明确撤回用 `status: withdrawn`，notes 保留准确撤回来源/位置和范围，不造替代端点。适用文本明确新增义务时可提取新义务；仅有无法解析的引用本身不产生新义务。

## L2
payload 支持 `superseded_by`、`supersede_relations` 和 `notes`，不另造 `change_chain` 对象。用真实 ID、来源文件 ID、位置和引文保留可审计说明。条款引用不存在、语言版本冲突或发布权威不明时保持 `pending_review`；未决解释不能支持确定不合规结论。投标同时提及新旧数值不自动视为合规，须按核实的有效义务检查一致性并报告矛盾。

参见[提取](requirement-extraction-rules.zh-CN.md)及[分类](requirement-classification-rules.zh-CN.md)。
