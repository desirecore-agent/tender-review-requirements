# 来源定位

## L0
定位必须能在清单中某个具体文件内导航到实际观察内容。非空字符串或重复占位符本身不是证据。

## L1
- PDF：使用从 1 计数的物理页，如 `p.1` 或 `p.12-15`。范围须为有序正数且不超过核实的 `physical_pages`。印刷页码、章节标签及页码映射写入 `notes`，不混入物理定位；不从印刷页码猜物理页。
- DOCX 和提取文本：保留实际提取工具给出的逻辑定位与索引约定。工具若输出从 1 开始的 `body:N`，引用该确切段落；若输出 `table:N/row:N` 且 row 0 为首个存储行，保留表头参与计数。不编造标题路径、不改变工具行号基数。重复标题须用明确的表格/段落身份和足够上下文保证可重定位。
- 标题/段落定位须确实可从文档提取结果恢复；任务说明记录约定，证据和覆盖两边一致使用。逻辑定位在校验器中按不透明字符串精确匹配，较宽泛的标题不会自动覆盖其下段落。
- 独立图片：引用实际图像文件及观察区域，采用可复现的区域约定。实际读取/渲染图片并报告可辨认程度；仅提取文字不能证明视觉特征、印章、签名或图表细节。
- 要求引用采用其权威 `source_file_id`；投标证据使用实际投标侧文件。present 证据须有同文件同位置 checked 覆盖，指定覆盖 ID 时只能由该项支持；物理页范围须区间完整覆盖。

## L2：位置未知或失败
不把通用未知位置标记写入条款或证据 location。无法取得确切引文/位置时，不创建该不完整条款行；将待提取部分列入 failed/unchecked 覆盖、发现局限及总审报告的未决/未查事项。不为通过 Schema 编造必填字段。仅有 method 的 checked 项可以说明做过某操作，却不能支持有位置的证据；失败或未读内容不能证明缺失。按授权重试渲染/提取或请求清晰来源，再以实际观察更新覆盖。

Unicode 十进制页码可以解析，生成定位优先使用普通十进制数字。未支持表达式、越界页码、文件路径、哈希和时间戳不能代替位置；格式示例只是约定，不是固定业务数值。

参见[提取](requirement-extraction-rules.zh-CN.md)。
